### Diagnóza: ImageServer vrací HTTP 500 nad ~7 Mpx
Regen NL/LS/SV (`--location NL/LS/SV` — pozor, CLI bere **kódy**, ne plné názvy) → všechny padly na
`urllib.error.HTTPError: HTTP Error 500` v `rock_relief.detect_rock_areas` → `dmr.fetch_elevation_grid`
(samostatný hi-res DMR fetch). Klíč: `fetch_elevation_grid` **cachuje** → 500 = cache miss = rock-relief
hi-res na NL/LS/SV v Sez. 63 **nikdy neuspěl** (jinak by byl v cache).

Empirický test (4× deterministicky, ne náhodný výpadek — terrain DMR menšího gridu přitom prochází, server
není dole):

| dotaz | Mpx | výsledek |
|---|---|---|
| 3000×2000 | 6,0 | OK |
| 3200×2133 | 6,8 | OK |
| 3500×2333 | 8,2 | **500** |
| 4000×2667 (NL @ 1,5 m) | 10,7 | **500** |

Práh ~7 Mpx na jeden `exportImage` (F32 tiff). Cache odhalila, proč Sez. 63 vypadal funkční — **míchané
rozlišení**: HS cache `2501×2501` = generováno s **TARGET_PX_M=2,0** (6,3 Mpx, pod prahem); NV cache
`2000×3334` = TARGET_PX_M=1,5 ale portrait 3×5 → jen 6,67 Mpx (pod prahem). Jen **6×4 landscape @ 1,5 m =
4000×2667 = 10,7 Mpx → 500**. `TARGET_PX_M` bylo během Sez. 63 zvednuté 2,0→1,5 kvůli detailu, čímž velké
výseky překročily práh; `MAX_PX=4000` clampuje **stranu** (4000), ne **plochu**, takže neochránil. Docstring
`rock_relief.py` navíc pořád tvrdil „≈ 2 m" (drift po té změně).

### Fix: plošný cap (volba uživatele — KISS)
`generator/rock_relief.py`: nová konstanta **`MAX_AREA_PX = 6_500_000`** (pod prahem; HS 6,3 Mpx prochází
opakovaně = doloženo) → clamp `gw_hi·gh_hi` odmocninou (škáluje obě strany rovnoměrně, poměr drží), stranový
`MAX_PX` ponechán jako sekundární pojistka pro extrémní poměry. Opraven docstring drift („≈ 2 m" → 1,5 m).
Výsledné rozměry: NL/LS/SV → 3122×2081 (1,92 m/px), HS → 2549×2549 (1,96 m), NV → 1974×3291 (1,52 m, portrait
se skoro vejde na cíl). Live fetch NL nových rozměrů **OK**. Tiling pro plné 1,5 m všude = budoucí (TODO).

Zvažovány a zamítnuty: **tiling** (víc kódu, Sez. 63 ho vědomě odložil) a **retry-degradace** (drží 1,5 m kde
server dovolí, ale rozlišení nekonzistentní mezi mapami). Plošný cap = nejmenší změna, sjednotí rozlišení.
