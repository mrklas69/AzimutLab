### Diskuse / co se dělalo

- **DRY paleta — oponováno směru z TODO.** TODO říkalo „paleta → jediný zdroj
  `isom-issprom.md`". Oponováno: runtime konzument je Python, parsovat Markdown za běhu
  je proti KISS. SSoT patří do kódu (`palette.py`), Markdown (spec §5, KB) na něj odkazuje.
  Uživatel souhlasil. Spec §5 ponechán jako jazykově nezávislá metodika + odkaz.
- **Mapový portál ČSOS → KB (ad-hoc požadavek).** Zdroj reálných OB map (cesta B).
  Licenci uživatel neznal → ověřena přímo ze stránky „O projektu": gate ZAVŘENA dvojitě
  (copyright klubů + jen náhledy 96 dpi s vodoznakem). Verify-against-source dotáhl
  „nevím" na jednoznačné NE.
- **Vektorizace vrstevnic — rozpleteny dvě vrstvy DAGu.** Uživatel narazil na „pixelové
  vrstevnice" + AutoTrace. Oponováno: pro náš generátor je AutoTrace ztrátová oklika —
  vrstevnice už JSOU polylinie z contourpy, jen je rasterizujeme do PNG (proto pixelové
  + PIL bez antialiasingu). Vektorizace rastru patří k reálným skenům (UC4-III/UC3).
  `lasertool` (lokální binárka) zhodnocen: LIDAR point cloud→rastr (Karttapullautin rodina),
  naráží na stejnou vegetace gate (multi-echo mračno). Multi-echo lze koupit → odloženo.
- **`.omap` — neslepě bez verify.** OOM nejdřív „nenalezen" (hledal jsem špatnou cestu),
  pak zjištěno, že 0.9.6 má jen `windows` platform plugin → headless konverze nejde.
  Rozděleny role: já píšu + self-verify (XML/struktura/rozsah), uživatel otevře v OOM.

### Rozhodnutí / nálezy

- **`palette.py` jako SSoT:** `PALETTE` slovník (slug→`Swatch(rgb, meaning)`) + odvozené
  `C_*` konstanty (žádná druhá kopie hodnot). Hex↔RGB byly konzistentní, ale na 2-3 místech
  (kód + spec §5 + §4.2-4.5) → reálné DRY riziko, ne hypotetické.
- **Vektor z přesného zdroje, ne z pixelů:** contourpy dává polylinie přímo → GeoJSON
  s ISOM symbolem 101/102. Georef: real = S-JTSK (EPSG:5514, přes zveřejněný
  `dmr.build_bbox`), noise = lokální metry. CRS member jen pro real (GeoJSON-2008,
  OOM/QGIS ho čtou). 103 Form line generátor nedělá.
- **`.omap` template-based (jako Pic2Omap `db2omap`), ale jiný vstup:** db2omap jde
  z rastru (pixel→coord přes .pgw/cv2), my z přesných polylinií → sdílíme jen FORMÁT,
  ne kód (CLAUDE.md: neduplikovat sourozence). Local CRS, paper-space (1 m→100 µm při
  1:10000, vycentrováno, bez Y-flip — gy roste dolů jako paper y). Symbol id z template.
- **ISOM symboly ověřeny** (O-Map Wiki): 101 Contour / 102 Index contour / 103 Form line.
  Malé uzavřené izolinie (lok. extrémy) → kartograficky bodové symboly 112/113/115/116
  (pozorováno uživatelem v .omap; zapsáno jako odložený bod do TODO).
