## Sezení 8 — Vektorizace vrstevnic na ISOM + DRY paleta + ČSOS KB

Osmé sezení projektu, první toho dne. `%BEGIN` proběhl: git čistý/synchronní.
**Audit cadence: LOC práh %AUDIT:CODE poprvé padl** (585 > 500 na začátku sezení,
po dnešku ~750 LOC / 5 modulů) — audit vědomě odložen (sezení produktivní na features),
ale je teď aktivní → první kandidát na Příště. Fokus zvolen uživatelem přes nabídku:
**DRY paleta** (foundations před dalším růstem kódu). Sezení se pak ad-hoc rozvětvilo
(ČSOS KB → vektorizace vrstevnic → `.omap`).

### Diskuse / co se dělalo

- **DRY paleta — oponováno směru z TODO.** TODO říkalo „paleta → jediný zdroj
  `isom-issprom.md`". Oponováno: runtime konzument je Python, parsovat Markdown za běhu
  je proti KISS. SSoT patří do kódu (`palette.py`), Markdown (spec §5, KB) na něj odkazuje.
  Uživatel souhlasil. Spec §5 ponechán jako jazykově nezávislá metodika + odkaz.
- **Mapový portál ČSOS → KB (ad-hoc požadavek).** Zdroj reálných OB map (cesta B).
  Licenci uživatel neznal → ověřena přímo ze stránky „O projektu": gate ZAVŘENA dvojitě
  (copyright klubů + jen náhledy 96 dpi s vodoznakem). Verify-against-source dotáhl
  „nevím" na jednoznačné NE.
- **Vektorizace vrstevnic — rozpleteny dvě vrstvy DAGu.** Uživatel narazil na „pixelové
  vrstevnice" + AutoTrace. Oponováno: pro náš generátor je AutoTrace ztrátová oklika —
  vrstevnice už JSOU polylinie z contourpy, jen je rasterizujeme do PNG (proto pixelové
  + PIL bez antialiasingu). Vektorizace rastru patří k reálným skenům (UC4-III/UC3).
  `lasertool` (lokální binárka) zhodnocen: LIDAR point cloud→rastr (Karttapullautin rodina),
  naráží na stejnou vegetace gate (multi-echo mračno). Multi-echo lze koupit → odloženo.
- **`.omap` — neslepě bez verify.** OOM nejdřív „nenalezen" (hledal jsem špatnou cestu),
  pak zjištěno, že 0.9.6 má jen `windows` platform plugin → headless konverze nejde.
  Rozděleny role: já píšu + self-verify (XML/struktura/rozsah), uživatel otevře v OOM.

### Rozhodnutí / nálezy

- **`palette.py` jako SSoT:** `PALETTE` slovník (slug→`Swatch(rgb, meaning)`) + odvozené
  `C_*` konstanty (žádná druhá kopie hodnot). Hex↔RGB byly konzistentní, ale na 2-3 místech
  (kód + spec §5 + §4.2-4.5) → reálné DRY riziko, ne hypotetické.
- **Vektor z přesného zdroje, ne z pixelů:** contourpy dává polylinie přímo → GeoJSON
  s ISOM symbolem 101/102. Georef: real = S-JTSK (EPSG:5514, přes zveřejněný
  `dmr.build_bbox`), noise = lokální metry. CRS member jen pro real (GeoJSON-2008,
  OOM/QGIS ho čtou). 103 Form line generátor nedělá.
- **`.omap` template-based (jako Pic2Omap `db2omap`), ale jiný vstup:** db2omap jde
  z rastru (pixel→coord přes .pgw/cv2), my z přesných polylinií → sdílíme jen FORMÁT,
  ne kód (CLAUDE.md: neduplikovat sourozence). Local CRS, paper-space (1 m→100 µm při
  1:10000, vycentrováno, bez Y-flip — gy roste dolů jako paper y). Symbol id z template.
- **ISOM symboly ověřeny** (O-Map Wiki): 101 Contour / 102 Index contour / 103 Form line.
  Malé uzavřené izolinie (lok. extrémy) → kartograficky bodové symboly 112/113/115/116
  (pozorováno uživatelem v .omap; zapsáno jako odložený bod do TODO).

### Kód / artefakty

- `sandbox/generator-poc/palette.py` (nový): paleta jako SSoT.
- `sandbox/generator-poc/omap_export.py` (nový): template-based `.omap` writer.
- `generator.py`: import palety, sběr vrstevnic + symbol, `_write_contours_geojson`,
  `--omap-template`, `TILE_M`, `ISOM_*` konstanty, meta `contours_vector`/`omap`.
- `dmr.py`: `_build_bbox` → veřejná `build_bbox` (georef vektoru i při cache-hit).
- Verify (ne odhad): GeoJSON real 67 / noise 68 linií, rozsah přesně 1465×1000 m;
  `.omap` self-verify (XML well-formed, 67 objektů, symbol 0×53/1×14, paper 146,6×100 mm),
  **finální verify uživatelem v OOM — vrstevnice sedí.**
- SLAP propsání: spec §5/§9, `isom-issprom.md`, `data-sources.md` (ČSOS + multi-echo),
  `tools-models.md` (lasertool/AutoTrace), `RESEARCH.md`, sandbox `README.md`, `.gitignore`
  (`lasertool/`).

### Kudos / Censure

- **Kudos! (oponování):** tři dobré odklony — paleta do kódu (ne MD), AutoTrace zbytečný

## Sezení 10 — Bodové symboly lokálních extrémů

Desáté sezení projektu, třetí toho dne. `%BEGIN` proběhl: git čistý/synchronní.
**Audit cadence: vše čerstvé** (CODE i DOCS proběhly Sez. 9) → zpátky k features.
**Stale práh padl: Cesty (§4.9)** byly 4. sezení v Příště → eskalováno DO/DROP;
uživatel zvolil **DO brzy** (→ `[!]` v TODO). Fokus zvolen uživatelem: **bod 1
z Příště — malé izolinie → bodové symboly** (čistý enabler-feeder, ne záclona).

### Diskuse / co se dělalo

- **Rozsah ISOM symbolů — oponováno TODO.** TODO chtělo 112/113/115/**116**. Oponováno:
  116 Pit je jiná feature class (umělá/erozní díra), z výškového pole **neodlišitelný**
  od 115 (oba jen lokální min) → cpát ho tam uměle = „náhodný soubor symbolů" (CLAUDE.md).
  Uživatel souhlasil: **112 knoll + 113 elongated + 115 depression**, 116 vynechán.
- **Výstup — raster + maska + meta, vektor odložen.** `.omap` point objekt by vyžadoval,
  aby template měl symboly 112/115 (forest template nejspíš nemá → fallback risk). GeoJSON
  body easy, ale i ty odloženy — raster + `mask_symbols.png` + `point_symbols` je samonosný
  UC5 přínos teď. (Rozhodnuto přes AskUserQuestion.)
- **Metoda detekce = přesně dle TODO.** Uzavřená smyčka (contourpy vrací vnitřní smyčky
  s prvním bodem == poslední) + plocha shoelace pod prahem + výška centroidu vs úroveň
  vrstevnice. Reklasifikovaná smyčka vypadne z vrstevnic, masky vrstevnic i vektoru —
  místo ní bodová značka (ISOM kartografická generalizace). Okolní větší vrstevnice zůstávají.

### Rozhodnutí / nálezy

- **Generalizace patří k §4.5 (vrstevnice), bodový výstup k §4.10.** Spec ukotven přes
  §4.10 (sekce „Bodové značky") + cross-odkaz z §4.5 → kódové komentáře (§4.10) zůstaly
  konzistentní bez churnu. Terénní knoll/depression jsou výjimka z det-řízených značek.
- **116 Pit / skalní 204/206 vědomě vynechány** — neodvoditelné z výškopisu (jiná feature
  class). Realistické ≠ náhodný soubor symbolů.
- **§8.1 `mask_symbols` konečně implementováno** — Sez. 9 audit (D5) ho značil jako chybějící.
  Multi-class (1=112 / 2=113 / 3=115). Bonus GT pro UC5 klasifikaci bodových symbolů.
- **Práh `KNOLL_MAX_AREA_M2` = 600 m²** (⌀ ≈ 28 m) dává ~10 % smyček jako symboly (7 z 63–67)
  na obou terénech — vizuálně vyvážené. Laditelná konstanta.

### Kód / artefakty
